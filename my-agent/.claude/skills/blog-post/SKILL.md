# 블로그 글 작성·발행

## 1. 유형 정하기
요청에서 유형을 판단하고, 애매하면 한 줄로 묻습니다. 구조는 `templates.md`를 따릅니다.

| 유형 | 코드 | 언제 |
|---|---|---|
| A vs B 비교 | `vs` | 두 제품/방식 중 고민 |
| TOP 3·5 추천 | `top` | 카테고리 추천 |
| 1개 제품 실사용 후기 | `review` | **강현님이 실제 구매·사용한 제품만** |
| 정보성 꿀팁 | `tip` | 사용법, 고르는 법, 관리법 |

`review` 유형은 강현님이 실제 사용한 제품이고, 사진을 보내 주는 것을 전제로 합니다.
경험 메모는 받지 않아도 됩니다. 아래 "경험 체크리스트"로 대신합니다.

## 경험 체크리스트 (`review` 유형, 강현님 시간 10초)
1. 조사 단계에서 구매자 상품평을 많이 읽고, 실사용자만 아는 구체적 경험을 8~12개 뽑습니다.
   (언박싱·냄새·설치 난이도·소음·크기 체감·계절/상황별 사용감·관리·내구성·아쉬운 점 등, 장점과 단점 섞어서)
2. 강현님 사진에서 보이는 것(사용 장소, 색상, 구성품, 함께 쓰는 물건)도 후보에 넣습니다.
3. 텔레그램으로 번호 목록을 보냅니다:
   ```
   강현님 경험과 맞는 걸 골라 주세요 👇
   1) 첫날 약간 냄새 → 하루 환기하니 사라짐
   2) 온도 올라가는 데 10분 정도
   3) 등 쪽에 선이 살짝 느껴짐
   ...
   "다 맞아" / "1,2,5" / "3번은 반대로 전혀 안 느껴짐" 처럼 답해 주세요
   ```
4. 고른 항목만 강현님 1인칭 경험으로 자연스럽게 풀어 씁니다. 강현님이 고친 내용은 고친 대로 씁니다.
   고르지 않은 항목은 빼거나 "다른 구매자들은 ~라고 하더라고요"처럼 씁니다.
5. 사용 기간·구매 가격처럼 체크리스트로 알 수 없는 사실은 같은 메시지에서 한 줄로 묻거나 생략합니다.

## 2. 조사 (브라우저)
- 쿠팡 상품 페이지: 가격, 스펙, 평점, 리뷰 수, 구매자 리뷰에서 반복되는 장점·단점
- 제조사 공식 정보, 필요하면 네이버 검색으로 키워드 확인
- 조사 메모는 `posts/<파일명>.md`에 출처 URL과 함께 저장

구매자 리뷰는 **분석 자료**로만 씁니다. "구매자 리뷰 ○○개를 보면 '등이 배긴다'는 평이 많았어요"처럼
출처가 드러나게 쓰고, 강현님의 경험인 것처럼 바꿔 쓰지 않습니다.

## 3. 원고 작성
- `posts/YYYY-MM-DD-슬러그.html`에 티스토리 HTML 모드에 붙여넣을 본문을 씁니다.
- 제목 1개 + 대안 2개, 태그 5~10개, 카테고리 제안.
- 쿠팡 파트너스 링크가 있으면 본문 맨 위에 공정위 문구를 넣습니다 (CLAUDE.md 참고).
- 분량 1,500~2,500자, 소제목(h2/h3), 표 1개 이상, 결론에 추천 대상 정리.
- 파트너스 링크는 강현님이 준 링크를 쓰거나, 쿠팡 파트너스 사이트에서 직접 생성합니다.

기록: `python3 tools/tracker.py post-add --type <유형> --title "<제목>" --file posts/<파일>.html`

## 4. 승인 요청 (텔레그램)
보낼 내용: 제목, 유형, 3줄 요약, 발행 방식(즉시/예약 시각), 카테고리·태그.
원고 전체가 필요하면 html 파일을 첨부합니다. **승인 전에는 발행하지 않습니다.**
수정 요청이 오면 반영 후 다시 승인을 받습니다.

## 5. 발행 (브라우저)
1. `https://todayshopping.tistory.com/manage/newpost` 열기 (로그인 안 돼 있으면 강현님께 로그인 요청)
2. 에디터 우측 상단 모드를 **HTML**로 전환 → 원고 붙여넣기 → 기본 모드로 돌아와 미리보기 확인
3. 제목, 카테고리, 태그 입력. 대표 이미지가 있으면 업로드
4. 발행 설정에서 공개 + (예약이면 날짜·시간 지정) → 발행
5. 발행된 글 URL 확인 후:
   `python3 tools/tracker.py post-update <ID> --status published --url <URL>` (예약이면 `--status scheduled --scheduled-at "YYYY-MM-DD HH:MM"`)
6. 텔레그램으로 "발행 완료 + 링크" 보고, 이어서 `index-request` 스킬로 색인 요청을 진행할지 묻거나,
   강현님이 "발행하면 색인까지 자동" 으로 정해 두었다면 바로 진행합니다.

## 실패 시
- 에디터 구조가 바뀌어 버튼을 못 찾으면 스크린샷을 보내고 멈춥니다. 추측으로 다른 버튼을 누르지 않습니다.
